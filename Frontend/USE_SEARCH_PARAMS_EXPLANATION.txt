In frontend/src/components/Products/SortOptions.jsx, this line:

const [searchParams, setSearchParams] = useSearchParams();

means:

1) useSearchParams() is a React Router hook.
2) It returns a tuple (an array with 2 values), similar to useState.
3) First value: searchParams
   - A URLSearchParams-like object for the current URL query string.
4) Second value: setSearchParams
   - A function that updates the browser URL query string (through React Router navigation behavior).

What each part does:

- searchParams.get("sortBy") reads ?sortBy=... from the URL.
- setSearchParams(...) writes query params back to the URL.
- Because the URL is part of routing state, your component re-renders when query params change.

So in this component, selecting an option updates sortBy in the URL, which makes sort state shareable and bookmarkable.

How it works under the hood (conceptually):

useSearchParams is built on top of React Router location/navigation hooks.

1) It reads location.search (the ?a=1&b=2 part).
2) It creates a URLSearchParams object from that string.
3) It gives you a setter that internally calls router navigation (navigate) with updated search.
4) Router updates history (push or replace), URL changes, and subscribed components re-render.

Mental model (simplified):

const location = useLocation();
const navigate = useNavigate();

const searchParams = new URLSearchParams(location.search);

function setSearchParams(nextInit, options) {
  const next = createSearchParams(nextInit); // normalizes object/string/URLSearchParams
  navigate({ search: `?${next.toString()}` }, options);
}

So useSearchParams is not just a parser; it is integrated with routing and React reactivity.

Difference between useSearchParams() and new URLSearchParams(...):

new URLSearchParams(...)
1) Native Web API.
2) Parses/manipulates query string data in memory.
3) Does NOT update URL by itself.
4) Does NOT trigger React re-render by itself.
5) No router integration.

useSearchParams()
1) React Router hook.
2) Returns current query params tied to route state.
3) Includes a setter that updates URL through router navigation.
4) Triggers route/state updates and re-render.
5) Works with browser history and SPA navigation.

Important practical nuance in your current code:

Current pattern:
searchParams.set("sortBy", sortBy);
setSearchParams(searchParams);

This often works, but a safer pattern is to create a new params instance before setting, to avoid mutation-related surprises:

const nextParams = new URLSearchParams(searchParams);
nextParams.set("sortBy", sortBy);
setSearchParams(nextParams);

This follows immutable React style more closely and avoids edge cases.

Extra note:

You can also choose whether changing sort should create a new history entry or replace the current one:
- setSearchParams(nextParams) -> default push behavior.
- setSearchParams(nextParams, { replace: true }) -> replace current history entry.
